# 划词图标浮现前先验证选区证据

ADR 0002 把触发一元化为划词图标后，macOS 端的手势检测（拖动超过阈值 / 双击抬起）只看手势形状，存在已知假阳性：双击空白、空白处拖动、拖窗口/拖文件都会浮出图标（Issue #2）。0002 原设想的补救「AX 命中测试过滤非文本位置」信号太弱：文本区域内的空白双击仍会命中文本元素，TUI（终端无原生选区）则完全无法区分，故弃用。

改为手势结束后、浮现图标前验证「选区证据」，二者满足其一才浮现：

1. **AX 选区**：焦点元素报出非空 `kAXSelectedText`——覆盖多数原生应用；
2. **剪贴板变动**：手势期间（mouseDown 到 mouseUp，另在 mouseUp 后 0.25 秒再看一眼）`changeCount` 变过——覆盖「选中即复制」、没有 AX 选区的应用（如 Claude Code 的 TUI，这是 SelectionCapture 剪贴板新鲜度兜底服务的同一批应用）。

两个信号都不亮则按假阳性丢弃。证据探测不在事件回调/主线程做：AX 询问对假死应用最多阻塞 0.3 秒×2 次，而事件监听挂在主线程 run loop 上，拖住主线程就是拖住全局事件投递（前车之鉴：AX 超时收紧到 0.3 秒那次加固）。改在串行后台队列探测，异步带来的过期结果用手势代数（generation，随每次按下/按键递增）丢弃。

## Consequences

- 接受两处已知偏差：
  1. AX 报不出选区、又不自动复制的应用（无障碍支持差的阅读器等）不再浮图标——菜单栏「解释当前选中」兜底；
  2. 焦点元素还留着历史非空选区时拖窗口，图标仍会浮出——严格说「存在非空选区」符合 Issue #2 的期望行为，靠图标超时消失兜底。
- 每次选取手势多花 1–2 次 AX IPC（正常应用约 1ms，无感；假死应用最坏 0.6 秒，图标晚现或不现）；每次左键按下多读一次剪贴板 `changeCount`（微秒级）。
- 对 Chromium 系应用（Electron 等）的 AX 询问可能促使其启用无障碍树，带来应用内一点常驻开销；此前点击图标取词时同样会发生，本决策把频次从「点图标时」提高到「每次选取手势」。
- 剪贴板信号可能被无关写入干扰（手势期间恰有其他进程写剪贴板则误浮图标）——窗口极短，接受。
