# macOS 载体的上下文尽力而为，拒绝截图方案

macOS 端取词后，「上下文」只在焦点元素通过 Accessibility 暴露全文（AXValue）时才可得；模拟 `⌘C` 兜底路径下只有选区本身，此时解释按无语境处理（系统提示词内建降级规则：按最常见义解释并点明歧义）。我们否决了「抓前台窗口截图交给多模态引擎当上下文」的方案：它虽然在任何应用里都能拿到完整语境，但要新增「屏幕录制」权限，并把整窗内容发给 Google——数据面远大于「选区±段落」，违背最小数据原则，同时拉高延迟与 token 成本。

代价是在终端等 AX 不友好的应用里，单词查询会系统性缺语境；缓解手段是把整句选上（句子自带语境，提示词的句子模式本来就会拆解难点词）。若实际体验证明缺语境伤害过大，截图方案可作为 v2 的显式开关重新引入。

## Considered Options

- **AX 尽力而为 + 无语境降级**（采用）
- **前台窗口截图 + 多模态引擎**（否决：新增权限、隐私面扩大、延迟与成本上升）
- **一律只发选区**（否决：对单词查询系统性放弃语境，而语境化恰是本产品存在的理由）
