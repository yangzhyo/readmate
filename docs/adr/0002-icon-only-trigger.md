# 触发一元化为划词图标，移除全部快捷键

macOS 载体最初按「仅快捷键」设计，实践中两条键盘路线都失败了：全局组合键会吞掉底下应用的按键（终端把 Option 当 Meta，编辑器/IDE 的组合键密度极高），换键只是打地鼠；双击裸修饰键无法吞事件，与其他全局监听工具（听写类常见）撞车时两边同时触发，技术上无解。更本质的是动线：在终端与桌面应用里选取文本只能用鼠标，手已经在鼠标上，「选中 → 顺手点图标」才是自然动作——浏览器插件的划词图标早已验证了这一点，也是用户的实际用法。

因此两个载体统一为「划词图标」唯一触发：插件移除 `Alt+T` 命令与图标开关（图标成为唯一触发后开关失去意义），macOS 端移除组合键与双击修饰键，改为监听选取手势（拖选/双击选词）浮现图标，菜单栏「解释当前选中」作零冲突兜底。

## Consequences

- macOS 端手势检测存在假阳性（拖窗口/拖文件也会浮出图标），以小图标、超时消失、随下次按键或点击收起来消化；后续可用 AX 命中测试过滤明显非文本的位置。
- 键盘无法唤出解释——接受，用户明确表示不用键盘流。`Esc` 关卡保留（属于关闭动作，不是触发快捷键）。
- 事件监听（辅助功能权限）仍是必需：手势检测与 `Esc` 吞键都依赖它。
